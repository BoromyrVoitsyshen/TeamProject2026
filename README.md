# 🚀 AI Chat - .NET Backend

Цей репозиторій містить бекенд для нашого командного проєкту ШІ-чату. Початковий концепт на Node.js було переписано на **C# (ASP.NET Core)** для кращої масштабованості, типізації та зручного розширення в майбутньому.

Проєкт побудовано за принципами **Vertical Slice Architecture** (кожна фіча має свою ізольовану папку з логікою) з використанням **Minimal APIs**.

## 🛠 Як запустити (Для всієї команди)

1. Переконайтеся, що у вас встановлено [.NET 8 SDK](https://dotnet.microsoft.com/download) (або новішу версію).
2. Відкрийте проєкт у Visual Studio / Rider або скористайтеся терміналом:

    dotnet run

3. Сервер запуститься, і в консолі буде вказано адресу (зазвичай `https://localhost:7106` або `http://localhost:5079`).
4. Відкрийте цю адресу в браузері — фронтенд завантажиться автоматично.

---

## Для Фронтенд-розробника

Бекенд повністю підтримує узгоджені API-контракти. Тобі не потрібно нічого змінювати у своїх запитах.

* **Де твої файли:** Уся клієнтська частина (HTML, CSS, JS) тепер лежить у папці `wwwroot/`. Сервер автоматично роздає її при запуску.
* **API:** Усі маршрути (`GET /api/chats`, `POST /api/chats/:id/messages` тощо) працюють як очікується. 
* **Виправлення:** В об'єкти розмов додано поле `updatedAt`, яке було відсутнє в початкових моделях, тому сортування і відображення часу в бічній панелі тепер працює коректно.
* **Файли:** Завантажені фотографії зберігаються локально і роздаються за адресою `/uploads/...`.

## Для AI-інженера (Інтеграція ШІ)

Наразі реальний штучний інтелект **не підключено**. Замість нього відповідає хардкодна заглушка. Твоє завдання — замінити її на виклик реальної моделі (наприклад, через Semantic Kernel, офіційні SDK від OpenAI / Anthropic / Google, або кастомні HTTP-запити до локальних Python-сервісів).

### Де писати код:
Твоя основна точка входу — файл:
`Endpoints/SendMessage/Endpoint.cs` (або відповідна папка фічі).

### Що потрібно врахувати:
1. **Поточна реалізація:** Зараз метод приймає повідомлення, зберігає його і миттєво генерує фейкову відповідь (`role: "assistant"`).
2. **Асинхронність та Тайм-аути:** Оскільки генерація відповіді ШІ може займати багато часу (до 1-2 хвилин), тримати HTTP-запит відкритим не завжди безпечно. Розглянь можливість винесення виклику моделі у фоновий процес (`IHostedService` або `BackgroundWorker`), поки бекенд одразу повертатиме статус-код фронтенду (фронтенд вміє опитувати сервер щодо статусу).
3. **Картинки:** Зображення приходять у `multipart/form-data`, бекенд вже зберігає їх на диск. Тобі потрібно буде конвертувати ці збережені файли у формат `Base64` (або інший, який вимагає API твоєї моделі) перед відправкою промпту.
4. **Контекст розмови:** Історія всього чату вже доступна в об'єкті `chat.Messages`. Тобі достатньо передати її в модель для збереження контексту.

## Структура проєкту (Для бекенду)

* `wwwroot/` — статика фронтенду.
* `Domain/` — базові моделі даних (`ChatSession`, `ChatMessage`).
* `Infrastructure/` — робота з файловою системою (`ChatStorage.cs`).
* `Endpoints/` — тут живуть усі API-маршрути (слайси). Кожна папка відповідає за одну конкретну дію (наприклад, `CreateChat`, `GetChats`, `SendMessage`).
* `data/` — генерується автоматично. Тут лежать `.json` файли розмов та завантажені фотографії (`uploads/`). **Цю папку додано в .gitignore.**

## Дані та БД
Поки проєкт на стадії прототипу, усі розмови зберігаються у звичайних JSON-файлах у папці `data/chats/`. Жодної бази даних розгортати не потрібно. Коли проєкт масштабується, ми замінимо `ChatStorage` на Entity Framework Core без змін у логіці контролерів.
